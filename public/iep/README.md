# 融IEP · 学前融合教育辅助 IEP 平台（可运行原型 v11.19）

## v11.19 改了什么（修旧电脑上扫描件识别不了的问题）

- **问题**：换电脑后上传医学诊断 / 量表扫描件，点「用本机识别引擎读字」失败。
- **根因（两个）**：
  1. vendor 里只内置了 **SIMD 版** wasm 核心（`tesseract-core-simd-lstm.wasm.js`）；
     浏览器 / CPU 不支持 WASM SIMD 的旧电脑需要**非 SIMD 版**，那个文件没打包；
  2. `ocr.js` 传给引擎的 `corePath` 是具体到 SIMD 文件的完整路径（`.js` 结尾），
     引擎源码里这个写法会**跳过 SIMD 探测直接加载该文件**，旧电脑上 wasm 编译即失败。
- **改法**：① 官方 CDN 补齐非 SIMD 核心 `tesseract-core-lstm.wasm.js`（3.9MB，vendor 现约 15MB / 6 文件）；
  ② `corePath` 改传**目录**，让引擎自行做 SIMD 探测、两版核心自动二选一；
  ③ 识别失败时的报错改为可执行的提示（缺哪个文件 / 需完整解压 / 换新版浏览器）。
- **注意**：旧电脑拿到新包后要**完整解压再打开**；若浏览器过旧（无 WebAssembly）会明确提示不支持本机识别。
- 顺带说明：土豆的四份报告（医学诊断 16 字段、PEP-3 17 字段、VB-MAPP 26 字段、感统 24 字段）
  已随「含数据」包内置，其它电脑打开即可见，无需重新上传解析。

## v11.18 改了什么（导入入口加到档案页，不用翻设置）

- **问题**：用户找不到「导入全量数据」——它原来只在「合规与设置 → 数据管理」（第 7 个标签）里。
- **改法**：「儿童档案」页顶部按钮行新增「**导入数据包**」（仅可编辑身份可见，带说明气泡），
  与设置页「导入全量数据」是同一个动作；设置页入口保留。另有提示：**更新过代码后需刷新页面
  （Ctrl+F5）才会出现新按钮**。

## v11.17 改了什么（「含数据」打包：换电脑打开即见全部学生数据）

- **需求**：把当前建立的学生数据打进包里，在其它电脑上打开系统就能直接读到；其它电脑上也能在
  数据归集台上传并解析文件。
- **实现**：新增 `assets/js/user-state.js` 预置数据包——打包时从本机浏览器导出的全量数据快照
  （23 份档案、已解析的医学诊断 / PEP-3 / VB-MAPP 报告、目标、成稿、AI 配置）。
  `store.js` 启动逻辑：**本机 localStorage 为空时**（= 新电脑 / 新浏览器首次打开）自动载入预置数据
  并立即写入本机 localStorage，之后一切读写走本机，不再依赖包。本机已有数据则完全不受影响。
- **其它电脑上传解析**：PDF（本地 pdf.js）、Word 解压、扫描件 OCR（本地 tesseract 中文包）全部
  内置在 `assets/vendor/`，离线可用——只需**解压整个文件夹**后双击 `index.html`（别在压缩包里直接
  双击；浏览器需较新的 Edge / Chrome）。
- **验证**（全新浏览器环境模拟其它电脑）：11 项断言全 PASS——23 份档案与当前档案自动载入、AI 配置
  随包、预置数据写入本机 localStorage、晓晓 5 字段与土豆 16 字段医学诊断忠实迁移、
  docx 上传 → 读文字层 → 字段校对 → 确认入档全链路可用、9 页 0 报错。
- **注意**：① `user-state.js` 是数据快照，本机后续改动不会自动同步进包——要更新包内数据，
  用「设置 → 数据管理 → 导出 / 导入」，或重新生成快照；② **含数据包内有真实学生档案与 API Key，
  请勿外传**，对外演示请用不含 `user-state.js` 的干净包。

## v11.16 改了什么（换电脑后数据迁移：补「导入全量数据」）

- **问题**：在其它电脑上读取不到医学诊断（以及自建档案、上传解析的报告）。根因：本系统是纯静态网页，
  所有数据存在**当前电脑 + 当前浏览器**的 localStorage 里，不跟着网页文件走——演示档案土豆有内置种子，
  但自己上传解析的医学诊断、自建档案只在本机；且设置页只有「导出全量数据（JSON）」，**没有导入**，
  导出的备份拿到另一台电脑也装不回去。
- **改法**：设置 → 数据管理新增「**导入全量数据（JSON）**」：
  - `store.checkImport(obj)` 只校验不落盘（非 JSON / 无 cases / 档案结构破损均拒绝并给出指引）；
  - 确认弹窗列明**将用文件里的 N 份档案（名单）替换本机现有 M 份档案**，提示先导出留底；
  - `store.commitImport(obj)` 写入 localStorage 后刷新页面，重走启动初始化与迁移链，
    旧版本导出的备份也能安全导入；
  - 导出文件新增 `savedAt` 时间戳，导入确认时显示备份导出时间；
  - 数据管理页新增「换电脑 / 换浏览器时数据不跟文件走」的操作指引说明。
- **验证**：20 项断言全 PASS——按钮与说明渲染、5 类坏文件拒绝、合法备份通过（档案数 / 名单 / 时间）、
  提交后标记字段与班级真的装回、**医学诊断 16 字段与诊断结论随备份完整迁移**、9 页遍历 0 报错。

## v11.15 改了什么（"现在"与成稿逐字一致 + AI 通读成稿自行定位）

1. **建议卡的"现在"就是成稿正在显示的文字。** 此前卡片读的是存储原文，成稿显示的是压缩/组装后的
   文字，两者对不上，老师无法确认"改的是不是这一条"。现在 `engine.js` 新增 `docAbilityLines` /

   生活自理·优势·追加；「情绪……急躁」→ 情绪行为·薄弱·追加；「感统课每周一次」→ 服务频次，
   均无需点名板块，pending = 0。

## v11.13 改了什么（能力分析"再增加一条"走追加模式，不再整栏重写）

- **问题**：纪要写"幼儿能力分析中情绪行为表现的优势能力再增加一条"，AI 却整栏重写，没基于现有内容追加。
- **根因**：字段清单里能力分析只有"整栏替换"一种入口，模型只能把 after 写成整栏新内容。
- **改法**：六维两栏各拆成两个字段——`ability.<领域>.strength/need`（整栏改写，after=全部条目）和 `...strengthAdd/needAdd`（追加一条，after 只写新增的那一条，原有条目由系统保留，物理上丢不了）；提示词同步规定"再增加/补一句/再加"一律选 Add 字段、绝不复述原有条目。
- **实测**：原话测试 → 模式=追加，原有 2 条全保留、新条目"接受具体表扬后能较快平静"接在末尾；"重新写一下，要突出深呼吸" → 模式=整栏改写、未提及条目保留。pending 均为 0。

## v11.12 改了什么（AI 解析"必须起草"：待确认基本清零）

- **问题**：老师给出建议后，AI 经常把它放进「需你确认/待补充」，尤其"新增条目"类（加目标、加策略），老师还得自己补写"改成什么"。
- **根因**：①系统提示词写的是"拿不准就放 pending、纪要没给的信息不要编造"，模型于是保守搁置；②字段清单里根本没有"新增长期目标"的入口（只能改已有目标），老师说"加一条长期目标"必然落进待确认。
- **改法**：
  - 提示词重写为"能起草就不要搁置"：口语/现象描述由 AI 转写成规范可测量表述；数量频次没给就用保守建议值并在理由里注明；pending 仅限三种情况（自相矛盾/与 IEP 无关/老师说先别改）。
  - 字段清单新增 `goal.new.<领域>`（六维各一个"新增长期目标"入口），after 两行 = 目标内容 + 通过标准。
  - 写回管道新增 `longAdd` 类型：自动生成不冲突的目标 id（如 `社交-3`）、type=会议新增、status=adopted，成稿第三章即渲染。
- **实测**（真实模型，5 条混合建议）：全部直接给出可采纳草稿、pending = 0；「土豆总是一个人待着」被起草成"在教师提示或同伴示范下，能主动向同伴发起互动（递玩具、说'一起玩'）"+ 可测量通过标准；采纳后新目标写入并在成稿出现。

## v11.9 改了什么（旧档案也能变成短稿：压缩函数下沉 + 生成链路收口）

v11.8 只改了内置样例数据，浏览器里已经存在的档案（土豆，8 条长句）不会跟着变——
因为迁移是按"首句指纹"判断的，旧数据首句和样例对不上，就被当成教师手改内容跳过了。
这一版把"短"做成三层保证：

| 层 | 做法 |
|---|---|
| 数据层（`data.js`） | 新增 `R.shortItem()`：去栏目前缀（"大运动："）、去句号、按逗号累加到 ≤20 字，停在完整分句上 |
| 迁移层（`store.js`） | `profileRev = p119`：内置土豆档案六维两栏**整格换成短稿**；其它档案里"条数 >4 或单条 >26 字"的格，就地压成一句话、最多 4 条 |
| 生成/渲染层（`engine.js` + `doc.js`） | 观察表联动的条目也走 `shortItem`；成稿渲染再兜一道：>26 字压短、一格最多 4 条，重复条目自动去重 |

实测：把土豆改成截图里那 8 条长句后刷新，六维变成 4/4、3/3、3/3、2/3、3/2、2/2、3/3，
最长一条 14 字，表高 680px；另一个档案里"该幼儿在集体活动中能够独立完成较长时间的桌面操作任务…"
被压成"该幼儿在集体活动中能独立完成较长时间的桌面操作任务"，不会串用土豆的文案。
`shortItem` 放在 `data.js`（最先加载），避免 `store.js` 迁移时 `R.engine` 还不存在导致的初始化中断。

## v11.8 改了什么（能力分析再压一档：每格 2–4 条、单条 ≈15 字）

对照教师手写 IEP 的写法，v11.7 虽然每条压成一句话，但一格仍有 5 条、单条 20–30 字，
读起来还是要"逐行读"。这一版按**扫一眼就看完**的密度重写：

| 维度 | 优势 | 薄弱与发展需求 |
|---|---|---|
| 大运动/精细动作 | 4 条 | 6 → **4 条**（合并"肢体位置感知"与"动作连续性"、"涂色"与"视线偏移"） |
| 语言沟通能力 | 3 条 | 5 → **3 条**（"举手回应少"并入"主动语言少"） |
| 社会交往能力 | 4 → 3 条 | 3 条 |
| 生活自理能力 | 2 条 | 3 条 |
| 认知学习能力 | 3 条 | 2 条 |
| 情绪行为表现 | 2 条 | 2 条 |
| 家庭养育情况 | 4 → 3 条 | 4 → 3 条 |

写法上三条规则：**一条一个信息点**（"跑、跳、爬、投掷熟练"不再写"等基础大运动掌握熟练"）、
**保留可测量的关键事实**（单脚站 3 秒、不会系扣/漱口、来园午睡易波动）、
**删掉评价性尾巴**（"存在一般问题""能力有待提升"这类不落到目标的词）。
总条数 46 → 40，最长一条 14 字，表高 885px → **680px**。

配套改动：

## v11 改了什么（排版对齐原稿 + 建议能读板块）

### 一、能力分析：按原稿的写法「一句一行」，不再糊成一大块

教师原稿里每一格其实是分点写的（`1.形状配对…2.认读数字…3.具备不错理解能力…`），之前提取成一整串、又叠了「·」项目符和来源角标，读起来又长又乱。现在改成：

| 之前 | 现在 |
|---|---|
| `· 1.形状配对、拼图能力优秀2.认读数字能力强，分类能力较好3.具备不错的理解能力；（档案录入）` | `1. 形状配对、拼图能力优秀`<br>`2. 认读数字能力强，分类能力较好`<br>`3. 具备不错的理解能力` |

切分规则：
- 句号 / 分号 / 问叹号 → 断行（引号里的问号不断，`"可以给我玩一下吗？"` 保持完整）
- 汉字后紧跟的 `2.` `3、` `（1）` → 断行并去掉原编号，由排版统一成条目
- **每格最多 3 条**（v11.3 起），条目带 `1. 2. 3.` 编号（只有 1 条时不编号）
- 单条超过 32 字时在逗号处收口加「…」（顿号次之，避免断成「可以拿取…」这种残片）
- 被略去的条目在格底标「另 N 条」，完整条目到「跨源能力画像」看，**成稿是摘要、画像页是详版**
- 只列要点，**不标来源**；出处统一在画像页与第一章「评估依据」表里追溯

> 为什么只留 3 条：成稿纸张宽 714px，能力分析表两列各约 271px，一行只放得下 20 字左右。条数再多，每格就折成 6～8 行，整张表 1300px 高，一屏看不完。3 条时整表约 1000px，一屏能看完，且句子基本完整。

### 二、短期目标：融合 / 小组 / 整合目标三层，逐条换行

原稿一格里的写法是 `融合：1.精细动作（1）…（2）…2.大运动（1）…小组：…整合目标：…`，一串到底。现在拆成三级版式：

```
融合
1. 精细动作
  （1）能用三指稳定捏取大颗粒物品，连续完成 3 次，物品不会轻易掉落。
  （2）双手配合，能够撕开包装纸。
2. 大运动
  （1）在少量口头提示下，能够独立沿着直线向前走 4-5 步…
小组
1. 单脚稳定站 8～10 秒
2. 连续向前跳 5～6 次落地稳定
整合目标
1. 单脚独立站 ≥5 秒（基线约 3 秒）
2. 双脚连续向前跳 3 次，落地基本稳定
```

- 解析：先按「融合 / 小组 / 整合目标」分块 → 块内按 `1. 2.` 分项 → 项内按 `（1）（2）` 分子条
- 「（1）」之前的短词（如「精细动作」）识别为小标题并加粗
- 没有自带编号的并列项（用分号罗列的）按顺序补 `1. 2. 3.`
- 新档案走 `gen.js` 自动组装，输出的是同款版式（融合 / 小组 / 整合目标三层齐全）

### 三、会议建议能自己判断"改哪一块"

以前只认「目标字段」（标准 / 策略 / 频次 / 主责）。现在先判**板块**，再判**动作**：

板块名与成稿章节标题**逐字一致**（卡片上的徽章显示的就是这张表的第一列，教师看到的名称和成稿里翻到的章节名相同）：

| 板块（= 成稿章节标题） | 听得懂的例子 | 写回到 |

## v9 改了什么（五条）

### 一、目标编号：单条不带序号

同一个能力维度只有 1 条目标时，编号就是维度名（`运动`、`语言`、`社交`、`认知`）；2 条及以上才带 `-1 / -2`（`自理-1`、`自理-2`）。

编号在 `gen.js` 生成候选目标后按维度统一重排；`store.goal(id)` 做了双向兜底（`社交` ↔ `社交-1`），所以旧决议、旧链接不会因为改编号而失效；会议页的"规则版"也改成**按维度定位**而不是写死编号。

### 二、成稿《幼儿能力分析》去掉"本期短期目标"一栏

第二章表格只剩三列：能力维度 / 幼儿现有优势能力 / 现存薄弱问题与发展需求（家庭养育情况行同步）。短期目标统一放在第四章，不再两处重复。

### 三、每一步都要用户确认，确认后先"分析计算"再跳转

原来点按钮直接跳页，现在统一走一个确认层：

```
数据归集台 →（确认：几份报告、几张观察表、完整度）→ 正在跨源分析计算…（4 步）→ 跨源能力画像
跨源能力画像 →（确认：几个维度有数据、几条候选目标）→ 正在按缺口生成建议… → 目标建议
目标建议 →（确认：待审议 N 条 / 已采纳 N 条）→ 正在汇总审议清单… → IEP 会议调校与审议
应用决议 →（确认：审议全部完成 + 勾选"我已逐条确认"）→ 正在应用决议并生成成稿… → 完整成稿
```

确认层不是纯弹窗：它把"这一步会用到什么数据、会算出什么、还剩什么缺口"列清楚，用户可以在这里就去补材料。计算动效是分步推进的进度条（读取 → 对齐 → 加权 → 生成依据链），每一步对应引擎里真实发生的动作。

### 四、会议纪要/大白话建议：提交 → 系统解析 → 逐条确认 → 回写成稿

`assets/js/suggest.js`（新增）做的是"读懂人话"：

| 读到什么 | 判定为 | 落到哪里 |
|---|---|---|
| `10 次里能回应 7 次` | 通过标准调整 | 该维度的目标 `criteria` |
| `先别定太高 / 加码 / 不再加码` | 降低难度 / 提高要求（否定式不误判） | 通过标准里的**通过数**按比例收放 |
| `别催他 / 用同一句提醒 / 步骤图 / 计时器 / 耳罩` | 支持策略补充 | 园内策略或家庭配合策略（自动区分场景） |
| `每周多加 2 次` | 练习频次 | 目标 `frequency` |
| `由感统教师负责` | 主责分工 | 目标 `owner` |
| `下学期再说 / 先放一放` | 延后 | 目标降级为学期后段 |
| `家长接送多沟通` | 成稿层面的事（不指向具体目标） | 追加到第六章「家长协作事项」 |

- 一句话能同时产出两条（"每周多加 2 次，由感统教师负责" → 频次 + 主责）。
- "每周多加 2 次"里的数字不会被当成通过标准（频次优先）；"不再加码"不会被当成提高要求（否定式）。
- 每条都给出 **原话 / 系统理解 / 现在 → 改为 / 影响位置**，教师逐条采纳、忽略，或一次性全部采纳（批量前先摊开对照表）。

## v7 改了什么（四条）

### 一、目标不再"空着"：按已入档的数据现算

之前把材料传完，"目标建议"里什么都没有——因为目标原来是一份写死的清单，只挂在土豆这份种子档案上，新建档案 `goals = []` 就没东西可渲染。

现在加了 **目标生成器**（`assets/js/gen.js`）：从六维推算结果反推候选目标。

| 步骤 | 做什么 |
|---|---|
| ① 找短板 | 取该维度所有参与计算的指标，按折算分从低到高排，最弱的那一项决定"这条目标写什么" |
| ② 选写法 | 17 套目标模板按最弱项命中（粗大动作→单脚站/跳；精细动作→三指捏取/串珠；提要求→跨情境"我要××"；社交→同伴呼唤的回应 …） |
| ③ 算因子 | 六个因子全部由数据算出，并给出每个值的一句话理由（见下） |
| ④ 出文本 | 目标 + 通过标准 + 融合/小组/整合三层长期目标 + 2–3 条短期目标 + 园内/家庭双策略 + 评量方式/频次/主责 |

**六因子怎么由数据算出**（不是手填）：

| 因子 | 由什么算 |
|---|---|
| 医嘱一致性 | 医学诊断的「诊断结论/主诉/现病史/发育史/言语评估/感统量表/ABC 分项目/诊疗计划」里是否点到这个维度 |
| 障碍严重度 | 该维度最弱指标折算分：<45→3、<60→2、<75→1、否则 0 |
| 跨源一致性 | 该维度参与计算的数据来自几个不同来源（PEP-3 / VB-MAPP / 感统 / 医学 / 观察表） |
| 功能性与参与必需度 | 离学期目标差多少分（≥8→2，≥4→1） |
| 家长诉求 | 家长观察表的优势/需求文本里是否提到这个维度 |
| 已有优势（负向） | 当前 ≥85 分→−2，≥78 分→−1，优势维度不重复设目标 |

**自己的目标不会被动**：材料补传后，只有当全部目标还是"机器生成 + 无人动过"时，才跟着自动更新；一旦教师采纳 / 改写 / 降级 / 忽略过任意一条，就停止自动更新，改用「按最新数据重新生成建议」按钮（会二次确认，说明会覆盖）。

### 一、扫描件也能读 —— 内置本机识别引擎

以前遇到扫描件只能"粘贴文字或手填"，现在**直接在浏览器里把字认出来**：

| 场景 | 处理 |
|---|---|

## 数据与引擎

- **六因子可解释评分**：医嘱一致性 / 障碍严重度 / 跨源一致性 / 功能性与参与必需度 / 家长诉求 / 已有优势（负向），六个因子可开关、可调权重，卡内可展开"为什么是 X 分"与依据原文。
- **能力指数 0–100**：仅用于同一儿童的时间序列比较（基线 / 当前 / 学期目标），**不是常模分**，不对儿童做横向排名。
- **同一把尺子**：画像页与进度页共用 `E.compare()`，基线一旦确定不换量表、不换折算规则，否则分不清是孩子变了还是尺子变了。
- **目标句式校验**：拒绝"提高 / 加强 / 改善"等不可观察动词单独成句，要求"情境 + 可观察行为 + 通过标准（次数 / 正确率 / 时长）"。
- **高风险识别**：材料或观察中出现自伤、伤人、走失、疑似虐待等表述时，不生成常规目标，改为转介流程指引并留痕。

## 技术说明

纯静态实现，无构建步骤：`index.html` + `assets/css/main.css` + `assets/js/{data,store,engine,gen,suggest,ui,ocr,parse,obs,app}.js` + `assets/js/views/*.js`。
经典 script 顺序加载（不用 ES module），因此 `file://` 直接打开也能运行。

第三方组件只有两个，都落在 `assets/vendor/`，都是 Apache-2.0，**都不联网**：

| 组件 | 版本 | 用途 | 体积 |
|---|---|---|---|
| pdf.js | 3.11.174 | 读 PDF 文字层、渲染扫描页图 | 约 1.5 MB |
| tesseract.js + chi_sim | 5.1.1 | 扫描件 / 图片本机文字识别 | 约 8.5 MB（含 SIMD-LSTM wasm 与中文模型） |

首次点「本机识别」要加载 wasm 与模型，约 2–4 秒，之后同页面内复用。

**多档案结构**：`state.cases = [{ id, meta, data }]`，`meta` 是档案头（编号 / 化名 / 班级 / 诊断 / 材料状态 / 缺口），`data` 是该儿童的目标、观察、会议、进度、成稿、日志。切档时把当前 `data` 挂到 `state` 顶层供视图读取，`R.CASE` / `R.DOMAIN_PROFILE` / `R.FAMILY_PROFILE` / `R.CHILDREN` 都是动态 getter，所以视图代码不用改一行就能跟着档案走。数据完整度按 `meta.materialStatus` 实时算：医学 25 + 教育评估 35（PEP-3 / VB-MAPP / 感统各 1/3）+ 教师观察 20 + 家长观察 20。

| 积木 / 组件 | 作用 |
|---|---|
| `U.pageHead({icon,title,sub,action})` | 页头：标题 + 一句说明 + 本页唯一主行动 |
| `U.hero({kicker,title,desc,action,side,tone})` | 焦点卡：把"现在该做什么"放在首屏，`tone='done'/'risk'` 切换状态色 |
| `U.tabs(ns, items)` | 分段导航：一页拆成几个动作，状态存在 `R.tabState[ns]` |
| `U.fold(label, body, {plain,tag,open})` | 折叠块（原生 `<details>`）：次要信息默认收起 |
| `R.REPORT_TYPES` | 四类报告的上传模板：字段、示例解析值、解析器（`buildStructured`）、六维映射（`ANALYZE_MAP`） |
| `R.store.report / saveReport / removeReport` | 单份报告的读取、解析确认入档、移除；同步 `materialStatus`、材料清单、完整度、操作留痕；入档时一并存原文摘录、字段依据、解析方式 |
| `R.parseFile(file)` | 文件 → 文字：PDF（pdf.js，blob worker）/ DOCX（ZIP + DecompressionStream）/ TXT / 图片；返回 `{kind, pages, text, lines, thumbs}`，扫描件 `kind='scan'` 并附页图 |
| `R.ocr.recognizePages(pages, onPage)` | 页图数组 → 文字：内置 tesseract.js 逐页识别（含增强与去噪），回调给进度；`supported()` / `warm()` / `close()` |
| `R.parse.ocr(thumbs, onPage)` | 解析层的扫描件入口，内部转调 `R.ocr` |
| `R.parse.extract(type, text, {ocr:true})` | 文字 → 字段：按四类报告版式抽取，返回 `{fields, conf, ev, meta, note}`（字段值 / 置信度 / 原文依据）；`ocr:true` 走 OCR 去噪口径 |
| `R.INDICATORS` | 六维加权指标表：每维由若干 `{src, k, w, how, pick?}` 组成，缺项权重按比例重分配，绝不造分 |
| `R.engine.compute()` / `profileComputed()` | 按上传数据逐项换算，返回每维的 `basis[]`（来源 / 数据项 / 原始值 / 换算 / 权重 / 得分）与 `missing[]` |
| `R.engine.goalBasis(g)` / `goalGap(g)` | 目标排序依据：该维度当前由哪些数据算出 + 维度缺口；`优先级 = 因子分 + 缺口 × 0.35` |
| `R.gen.list()` / `apply()` / `auto()` | 目标生成器：从六维反推候选目标（模板按最弱项命中），六因子逐项由数据算出；`auto()` 只在"没人动过"时跟着材料更新 |
| `R.engine.docByDomain()` | 成稿取目标：优先已采纳，一条都没采纳时退回全部候选并标注"待审议" |
| `R.store.suggest / applySuggest('empty'\|'all')` | 解析结果 → 六维建议；默认只补空缺维度，不覆盖教师已定的分数 |
| `U.radar({axes, series})` | 手写 SVG 雷达图：多序列多边形 + 网格环 + 轴标签分值，用于六维能力画像与干预前后对比 |
| `U.compareBars(rows)` | 成对条形 + 目标虚线刻度，用于"每个维度：基线 / 当前 / 学期目标" |
| `U.donut(pct,{size,sw,color,unit})` | 手写 SVG 环形图，用于完整度与目标审议占比 |
| `U.dualBars(list)` | 当前 vs 学期目标的叠加双条（浅底为目标、实条为当前、虚线为刻度） |
| `U.confirmStep({title,checks,calcSteps,to})` | 分步确认层：列出这一步用到/缺什么，确认后播计算动效再跳转 |
| `U.computing(title, steps, done)` | "正在分析计算"全屏遮罩，分步点亮，结束后回调 |
| `R.actions.stepNext(key)` | 流程四段的确认 + 计算 + 跳转（`intake-profile` / `profile-goals` / `goals-meeting` / `meeting-doc`） |
| `R.suggest.analyze(text)` / `apply(item)` | 会议纪要与大白话建议解析：句子 → **板块（八块）** → 维度 → 意图 → 字段/目标/章节 → 前后对照；采纳后写回 |
| `R.suggest.plans` | 成稿八个可改板块的定义（key / 名称 / 触发词），卡片上的板块徽章取这里 |
| `R.store.setDomainCell(code, side, text, mode)` | 写能力分析某一格（`strength` / `need`，`mode: append / replace`），成稿第二章随之更新 |
| `R.store.addShort(goalId, text, crit)` | 给某条目标追加短期目标，并清掉 `shortDetail` 快照让成稿重排 |
| `sentLines(text)` / `shortBlocks(text)`（doc 视图内） | 长文本分句成行 / 短期目标三段两层解析，是 v11 排版的核心 |
